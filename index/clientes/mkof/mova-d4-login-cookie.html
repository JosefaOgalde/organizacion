Día 4 — Login único + cookie

acme-chile.cl · Tarea mkof/04 · 19 jul 2026

Solo diseñar — no implementar en servidor

Flujo objetivo

1. Pide módulo → 2. guard.php → 3. ¿sesión? → No → login?redirect= / Sí → entra 
Usuario → /mova/erp/
  → guard.php
  → sin sesión → login.php?redirect=/mova/erp/
  → login OK → cookie HttpOnly+Secure
  → vuelve a /mova/erp/
PUENTE El núcleo D3 define los archivos. D4 define cómo viaja la sesión: cookie en servidor, nunca JWT en el navegador. 
Archivos núcleo → cookie PHP · HttpOnly+Secure · Google alimenta sesión (no localStorage)

Especificación de cookie

ParámetroValorMotivo
NombrePHPSESSID o MOVASESSIDUn solo nombre en todo el sitio
HttpOnlytrueJS no puede leerla
SecuretrueSolo HTTPS
SameSiteLaxCSRF básico + redirect post-login
Path/Compartida entre módulos
Lifetime0 (sesión) o 8–12 h máx.Evitar sesión eterna
Prohibido: JWT / access_token / token Google en localStorage o sessionStorage. Google OAuth puede usarse, pero el resultado vive en sesión PHP emitida por mova_auth.

Correo+clave y Google sin fragmentar

Correo + clave

Form en login.php → valida → crea sesión PHP.

Google OAuth

tokeninfo + whitelist → misma sesión PHP. El panel /mova/ deja de ser puerta directa.

Redirect seguro

  • Solo paths que empiecen con / del mismo sitio.
  • Rechazar http://, //evil.com.
  • Whitelist opcional: /mova/, /axon/, /rrhh/, /admin/.
  • Default si inválido: /mova/.
  • Excluir del guard: login, logout, validate, /documentos/.
